## Answer

In this workspace (the **Reflex** framework), the "derived state variable class" is `ComputedVar` (`reflex/vars/base.py:2055`, created via `@rx.var`/`@cached_var`), and its computation-function accessor is the `fget` property (`reflex/vars/base.py:2524-2531`), which returns the user-defined getter stored in `self._fget`. That function plays a **dual role**: it is both the runtime value computer and the *static analysis target from which the dependency graph is derived*.

### 1. Runtime role — computing the derived value
In `ComputedVar.__get__` (`base.py:2387-2398`), `self.fget(instance)` is invoked to produce the value, either on every access (`cache=False`) or only when the cached value (`_cache_attr`) is missing or the var `needs_update`.

### 2. Dependency-tracking role — bytecode analysis of the function
The key mechanism for recomputation tracking happens in `ComputedVar._deps()` (`base.py:2411-2460`):

- When `auto_deps=True`, `_deps` takes `self._fget` and hands it to `DependencyTracker` (`reflex/vars/dep_tracking.py:50`).
- `DependencyTracker._populate_dependencies()` disassembles the function's **bytecode** (`dis.get_instructions`) with a small state machine to find every state var the computation *reads*: attribute loads on `self`, locals bound from `get_state(...)` calls, vars passed to `get_var_value(...)` (whose source is re-extracted and evaluated), plus recursive analysis of nested functions/comprehensions and called methods/properties.
- The output is a dict mapping state names → sets of var names the computed var depends on. If analysis fails, Reflex warns and falls back to the user-provided `static_deps` (`base.py:2454-2460`).

### 3. Wiring into the state's dirty-tracking system
At state-class construction, `BaseState._init_var_dependency_dicts()` (`reflex/state.py:769-800`) calls `cvar._deps(objclass=cls)` for each **cached** computed var and *inverts* the result into:
- `_var_dependencies`: base-var name → set of `(state_full_name, computed_var_name)` pairs that depend on it (`state.py:340`);
- `_potentially_dirty_states`: substates that may need recomputation when a var here changes.

(Non-cached vars skip dependency analysis entirely — they're placed in `_always_dirty_computed_vars`, `state.py:802-807`.)

### 4. Driving recomputation
When a base var is assigned, `__setattr__` adds it to `dirty_vars` and calls `_mark_dirty()` (`state.py:1420-1426`). Then `get_delta()` → `_mark_dirty_computed_vars()` (`state.py:1947-1972`) uses `_dirty_computed_vars()` (`state.py:1986-2003`), which looks up `_var_dependencies` for each dirty var, invalidates each dependent `ComputedVar`'s cache (`mark_dirty` deletes `_cache_attr`, `base.py:2462-2469`), and adds it to `dirty_vars` — iterating until the transitive closure (computed vars depending on computed vars) is stable.

### Summary
The function returned by the `fget` accessor is the *single source of truth* for automatic dependency detection: its bytecode is statically analyzed once at class-definition time to build the var → computed-var dependency map, which at runtime determines exactly which derived vars get marked dirty (cache-invalidated) and recomputed — and re-sent in the delta — whenever a state var they read is modified. Without it, `ComputedVar` would either have to recompute on every access or require manually declared `static_deps`.
