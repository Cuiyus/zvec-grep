Follow-up with three further findings, all reproduced. A self-contained script for the first
two is at the end of this comment; the third is a two-line variation on it.

### 1. The tail loss is only the visible part: `optimize()` also shifts the id → vector mapping

The documents that survive do not hold their own vectors. Every document written after the
first superseded row ends up holding the vector of the document written K positions later,
where K is the same number of superseded rows. The id is correct, the scalar fields are
correct, search returns the document — but the vector stored under it belongs to a different
document. So the collection does not merely lose its tail: it answers with wrong content
across almost its entire contents.

Numbers from the script below (1000 documents, 3 of them re-upserted, HNSW/COSINE, dim 32),
identical on the writer handle and on a reopened read-only handle:

```
A-control: 1000 inserts, nothing superseded, optimize()
  same handle:           doc_count=1000   holds own vector=1000   holds a foreign vector=0      missing from search=0
  reopened read-only:    doc_count=1000   holds own vector=1000   holds a foreign vector=0      missing from search=0

B-default-order: 1000 inserts, 3 re-upserted, optimize()
  same handle:           doc_count=1000   holds own vector=0      holds a foreign vector=997    missing from search=3
                         offset (own position - holder position) -> documents: {-997: 3, 3: 994}, reference vectors held by nobody: 3
  reopened read-only:    doc_count=1000   holds own vector=0      holds a foreign vector=997    missing from search=3
                         offset (own position - holder position) -> documents: {-997: 3, 3: 994}, reference vectors held by nobody: 3
```

Not one of the 1000 documents holds its own vector. 994 of them are shifted by exactly +3
(= K), and the 3 re-upserted rows moved to the tail of the compacted set, which produces the
second offset.

The position of the superseded row sets the boundary: everything written after it is shifted,
everything before it is intact. Measured on 1000 documents with a single re-upsert
(misaligned / intact): first position → 999 / 0, middle → 499 / 500, last position → 0 / 999.
One superseded row at the start of the collection is therefore enough to misalign all the
rest. On a larger collection — 20 000 documents, 400 superseded rows — 19 964 of 20 000
documents fail a "search for me with my own vector" check.

This was confirmed twice independently: two separate reproductions, written from scratch by
different people, different probes (orthonormal basis vectors and random unit vectors) and
three independent read paths (vector search, `fetch(include_vector=True)`, `iter_docs()`).
`FLAT` was clean in every one of those runs, `HNSW`, `IVF` and `VAMANA` were all affected;
metric (IP, COSINE, L2), vector dimension, segment count and collection size made no
difference.

Two consequences worth knowing:

- **`fetch()` cannot be used to read a vector back for repair.** It returns the same shifted
  mapping — a foreign vector — while the scalar fields of the same document are correct. So
  the collection itself is not a usable source of the original vectors, and re-upserting only
  the documents that disappeared does not fix it: the rest keep answering with foreign
  content.
- **A health check that searches by document id cannot see this.** With
  `Query(field_name, id=...)` the engine takes the document's (foreign) vector and searches
  with it, and the index returns that very document, so the check passes on a fully misaligned
  collection — 980 of 990 documents reported as "fine" in one such run. Only a search with a
  vector held outside the collection detects it.

### 2. Narrower trigger condition: it only happens when that `optimize()` is the first one to compact any content

If the collection is compacted once before any row is superseded, everything afterwards stays
correct — later overwrites, deletes and further `optimize()` calls included. From the same
script:

```
C-optimize-first: 1000 inserts, optimize(), 3 re-upserted, optimize()
  same handle:           doc_count=1000   holds own vector=1000   holds a foreign vector=0      missing from search=0
  reopened read-only:    doc_count=1000   holds own vector=1000   holds a foreign vector=0      missing from search=0
```

The only difference from scenario B is one extra `optimize()` before the re-upsert. The same
holds with `delete()` instead of `upsert()`, and at other sizes: in a separate measurement on
a dense+sparse schema, "write 200 → overwrite 3 → append 20 → optimize()" gave 217 of 220
documents misaligned, while "write 200 → optimize() → overwrite 3 → append 20 → optimize()"
gave 220 of 220 intact; with 3 deletions instead of the overwrites, 214 of 217 misaligned
versus 217 of 217 intact.

Two refinements that matter if this is turned into advice:

- **The protective `optimize()` must actually compact something.** `optimize()` on an empty
  collection is a no-op — 0.03 ms, no new files — and gives no protection whatsoever:

  ```
  E-empty-optimize-first: optimize() on the empty collection, 1000 inserts, 3 re-upserted, optimize()
    same handle:           doc_count=1000   holds own vector=0      holds a foreign vector=997    missing from search=3
  ```

  Compacting a *single* document is enough (about 30 ms), and that is durable:

  ```
  D-one-doc-first: 1 insert, optimize(), 999 inserts, 3 re-upserted, optimize()
    same handle:           doc_count=1000   holds own vector=1000   holds a foreign vector=0      missing from search=0
    reopened read-only:    doc_count=1000   holds own vector=1000   holds a foreign vector=0      missing from search=0
  ```

  In a longer run, an early `optimize()` over 10 documents protected a collection that then
  received 5000 more writes with 1000 overwrites and 100 deletes — 4910 of 4910 correct.
- **The immunity is a property of the directory, not of the open handle.** It survives
  closing and reopening the collection, and copying the directory.

Building the index with a separate call over already-loaded data also produced a correct
result in every run we tried, which may point at the same place in the code as the "first
compaction" condition does.

For users this is a usable workaround — call `optimize()` once, right after the first batch is
written and before the first overwrite or delete. For you it may narrow down where the rebuild
path differs.

### 3. Reading vectors for many documents on a badly corrupted collection kills the process

Not an exception — a segmentation fault, exit code 139, no Python traceback. A user who tries
to inspect a corrupted collection loses the process instead of getting a diagnosis.

Reproduced three times here with the script below changed to `N = 10_000`, `K = 1_000`,
`DIM = 1024`, and with the probe replaced by `coll.fetch(ids)` (vectors are included by
default) over all ids in batches of 1000. The process dies on the first batch, both with a
dense-only schema and with a dense+sparse one.

Vector size is part of it: the same 10 000 documents with 1000 superseded rows at `DIM = 32`
survive the whole pass (9000 of 10 000 read back, 1000 missing, no crash). Earlier runs on
other collections put the threshold at roughly 200–300 unreadable documents read within one
process, and smaller batches do not help — 10 000 documents with 300 unreadable, read in
batches of 100, died on the third batch. `Query(field_name, id=...)` (search by document id,
where the engine fetches the vector itself) kills the process the same way.

What survives a badly corrupted collection: `fetch(ids, include_vector=False)`, searching with
a vector supplied from outside, and `iter_docs()` — the last one raises
`RuntimeError: vector fetch failed, field: <name>: Failed to fetch vector from index` instead
of crashing.

### Reproduction script for 1 and 2

Same environment as the original report (zvec 0.7.0, Python 3.12.13, Windows 11); numpy 2.4.6
in this run. Runs in a few seconds, creates its collections next to the script file and
removes them afterwards, exits with code 1 when the misalignment reproduces. Three consecutive
runs produced byte-identical output.

```python
"""Follow-up reproduction for the optimize() defect: it does not only drop the
tail of the collection, it also shifts the id -> vector mapping of every
document written after the first superseded row. And it only happens when that
optimize() is the first one to compact any content.

Probe: every document i is written with a known reference vector v_i. After
optimize() we query with v_i and ask who comes back on top. On a healthy
collection the answer is always document i itself.

Only zvec and numpy are needed; vectors are deterministic (fixed seed).
Collections are created next to this file and removed afterwards.
Exit code 1 means the misalignment reproduced, 0 means it did not.

    pip install zvec==0.7.0 numpy
    python repro_followup.py
"""

import gc
import platform
import shutil
import sys
from collections import Counter
from pathlib import Path

import numpy as np
import zvec

SEED = 20260905
DIM = 32
N = 1000  # documents inserted
K = 3  # documents later re-upserted -> K superseded rows

ROOT = Path(__file__).resolve().parent / "work-followup"


def build_schema() -> zvec.CollectionSchema:
    return zvec.CollectionSchema(
        name="followup",
        fields=[zvec.FieldSchema("doc_id", zvec.DataType.STRING, nullable=False)],
        vectors=[
            zvec.VectorSchema(
                "dense",
                zvec.DataType.VECTOR_FP32,
                dimension=DIM,
                index_param=zvec.HnswIndexParam(metric_type=zvec.MetricType.COSINE),
            )
        ],
    )


def close(coll):
    if hasattr(coll, "close"):
        coll.close()
    del coll
    gc.collect()
    return None


def doc_id(i: int) -> str:
    return f"doc-{i:05d}"


def index_of(ident: str) -> int:
    return int(ident.split("-")[1])


def ref_vector(i: int) -> list:
    """Reference vector of document i. Distinct for every i, fixed seed."""
    rng = np.random.default_rng(SEED + i)
    v = rng.standard_normal(DIM).astype(np.float32)
    v /= np.linalg.norm(v)
    return [float(x) for x in v]


def make_doc(i: int) -> zvec.Doc:
    return zvec.Doc(id=doc_id(i), vectors={"dense": ref_vector(i)}, fields={"doc_id": doc_id(i)})


def upsert(coll, indices) -> None:
    for start in range(0, len(indices), 200):
        statuses = coll.upsert([make_doc(i) for i in indices[start : start + 200]])
        statuses = statuses if isinstance(statuses, list) else [statuses]
        assert all(s.ok() for s in statuses), statuses
    coll.flush()


def probe(coll) -> dict:
    """Who holds which reference vector, and who is searchable at all."""
    own, shifts, orphaned = 0, Counter(), 0
    for i in range(N):
        hits = coll.query(
            zvec.Query(
                field_name="dense", vector=ref_vector(i), param=zvec.HnswQueryParam(ef=64)
            ),
            topk=1,
            output_fields=[],
        )
        # COSINE returns a distance, so an exact match scores 0.0. Anything else
        # means no document in the index holds this reference vector at all.
        if not hits or hits[0].score > 1e-4:
            orphaned += 1
            continue
        top = str(hits[0].id)
        if top == doc_id(i):
            own += 1
        else:
            shifts[i - index_of(top)] += 1

    wide = coll.query(
        zvec.Query(field_name="dense", vector=ref_vector(0), param=zvec.HnswQueryParam(ef=1000)),
        topk=N,
        output_fields=[],
    )
    present = {str(h.id) for h in wide}
    missing = [doc_id(i) for i in range(N) if doc_id(i) not in present]
    return {
        "doc_count": int(coll.stats.doc_count),
        "own": own,
        "foreign": sum(shifts.values()),
        "orphaned": orphaned,
        "shifts": dict(shifts),
        "missing": missing,
    }


def report(label: str, r: dict) -> None:
    print(
        f"  {label:<22} doc_count={r['doc_count']:<6} holds own vector={r['own']:<6} "
        f"holds a foreign vector={r['foreign']:<6} missing from search={len(r['missing'])}"
    )
    if r["shifts"] or r["orphaned"]:
        print(
            f"  {'':<22} offset (own position - holder position) -> documents: {r['shifts']}, "
            f"reference vectors held by nobody: {r['orphaned']}"
        )


def scenario(name: str, description: str, steps) -> dict:
    path = ROOT / name
    if path.exists():
        shutil.rmtree(path)
    coll = zvec.create_and_open(str(path), build_schema())
    try:
        steps(coll)
        print(f"\n{name}: {description}")
        r = probe(coll)
        report("same handle:", r)
    finally:
        coll = close(coll)

    coll = zvec.open(str(path), zvec.CollectionOption(read_only=True))
    try:
        ro = probe(coll)
        report("reopened read-only:", ro)
    finally:
        coll = close(coll)
    shutil.rmtree(path, ignore_errors=True)
    return ro


def a_control(coll) -> None:
    upsert(coll, list(range(N)))
    coll.optimize()


def b_default_order(coll) -> None:
    upsert(coll, list(range(N)))
    upsert(coll, list(range(K)))  # re-upsert K existing ids -> K superseded rows
    coll.optimize()


def c_optimize_first(coll) -> None:
    upsert(coll, list(range(N)))
    coll.optimize()  # first optimize() sees no superseded rows
    upsert(coll, list(range(K)))
    coll.optimize()


def d_one_document_first(coll) -> None:
    upsert(coll, [0])
    coll.optimize()  # compacts a single document, ~30 ms
    upsert(coll, list(range(1, N)))
    upsert(coll, list(range(K)))
    coll.optimize()


def e_empty_optimize_first(coll) -> None:
    coll.optimize()  # nothing to compact -> no protection
    upsert(coll, list(range(N)))
    upsert(coll, list(range(K)))
    coll.optimize()


def main() -> int:
    print(f"zvec {zvec.__version__} | numpy {np.__version__}")
    print(f"Python {sys.version.split()[0]} | {platform.platform()}")
    ROOT.mkdir(parents=True, exist_ok=True)
    try:
        a = scenario("A-control", f"{N} inserts, nothing superseded, optimize()", a_control)
        b = scenario(
            "B-default-order", f"{N} inserts, {K} re-upserted, optimize()", b_default_order
        )
        c = scenario(
            "C-optimize-first",
            f"{N} inserts, optimize(), {K} re-upserted, optimize()",
            c_optimize_first,
        )
        d = scenario(
            "D-one-doc-first",
            f"1 insert, optimize(), {N - 1} inserts, {K} re-upserted, optimize()",
            d_one_document_first,
        )
        e = scenario(
            "E-empty-optimize-first",
            f"optimize() on the empty collection, {N} inserts, {K} re-upserted, optimize()",
            e_empty_optimize_first,
        )

        print("\n" + "=" * 78)
        ok = a["own"] == N and b["own"] == 0 and c["own"] == N and d["own"] == N and e["own"] == 0
        print(
            f"documents holding their own vector: control {a['own']}/{N}, "
            f"default order {b['own']}/{N}, optimize-first {c['own']}/{N}, "
            f"one-doc-first {d['own']}/{N}, empty-optimize-first {e['own']}/{N}"
        )
        if ok:
            print(
                "REPRODUCED: optimize() shifted the id -> vector mapping of every surviving\n"
                "document; running one optimize() over any non-empty content beforehand\n"
                "avoids it, while an optimize() on the empty collection does not."
            )
        else:
            print("NOT reproduced as expected.")
        return 1 if ok else 0
    finally:
        shutil.rmtree(ROOT, ignore_errors=True)


if __name__ == "__main__":
    sys.exit(main())
```
