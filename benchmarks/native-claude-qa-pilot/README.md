# Native Claude Code + Qwen pilot

This separate pilot tests the main benchmark's native Claude agent with the existing Qwen Anthropic endpoint. The main registry supports Claude/Opus only, so a small explicit routing adapter selects Qwen without editing the registry or the native agent loop.

The completed [q001 confirmation](results/20261020-confirmation-v1/README.md) and [q002/q003 expansion](results/20261020-expansion-v1/README.md) did not establish a stable favorable benchmark set. The user cancelled the original three-task repetition campaign and limited the next cohort to q001. The [completed q001 repetition study](results/20261020-zvec-q001-repeat-v1/README.md) retains ten fresh baseline and ten fresh zg executions. Reported input fell 36.08%, but full-slot time fell only 0.47% with an interval crossing zero. Score-tail trimming widened resource-comparison intervals under every reported rating interpretation. Source-scope failures and unresolved C7 judgments remain visible; this study establishes no stable favorable case. Historical and cancelled-run observations are excluded.

The [completed live v2 pair](results/20261020-live-v2/README.md) passed both independent execution/source audits and blinded quality review. Both answers scored 8/10 and passed; zg reported input including cache fell 63.27%, native execution wall fell 20.24%, and full slot wall including fresh indexing fell 5.24%. This meets the prospectively frozen reported-input development candidate rule. It is one previously exercised task and one pair, not a confirmed stable benefit or a favorable benchmark set. All raw answers, logs, independent reviews and the unchanged primary grading are retained.

The user's subsequent variability requirement is implemented in the separate [statistics adapter](robust_statistics_v1.py), borrowing [PR #261](https://github.com/zvec-ai/zvec-grep/pull/261) at `5d9fc0174cd2e4baad6337164fa1abb87f900839`. It reports raw, score-trimmed and task-screened means with equal weight per task. Exactly one lowest and one highest score are removed within each task/profile when at least three trials exist; ties use trial index then original position. Every resource metric uses those same retained tuples. The planned full experiment uses ten executions per task/profile. After trimming, score sample SD and time/input-token CV are maximized across profiles for each task. A single upper-tail MAD pass screens tasks with modified Z strictly above 3.5, using the same final task set for every profile and metric. Fewer than five tasks, missing dispersion or zero MAD explicitly disable the applicable screening. Original evidence and quality/execution decisions remain retained.

The [pinned reference and validation](provenance/robust-statistics-pr261-v1/provenance.json) retain the original source and tests. Eleven selection/numeric source nodes are byte-identical; fourteen unchanged upstream test bodies and seven native-adapter tests passed. The native adapter keeps the input/accounting scope explicit, accepts separately named native and outer-slot time measurements, and preserves unknown monetary cost. This analysis was introduced after q002 outcomes had been observed and while q003 was executing; it supplements the frozen phase decision. The current two-task, one-pair-per-task expansion cannot estimate residual variability, so all observations remain and both trimming and task screening are explicitly unavailable. A passing or failing quality decision alone is never an outlier rule.

To analyze normalized native evidence without model calls, run `python robust_statistics_v1.py input.json new-report.json`. Input contains explicit `measurement_scope` and `time_scope` strings plus `cases`; each case has a unique `task_id` and `profiles.baseline.trials` / `profiles.zvec-grep.trials`. Each original trial supplies matching positive `trial_index`, `judge.total`, and numeric `metrics.input_tokens`, `output_tokens`, `tool_calls`, `agent_wall_seconds`; optional numeric measurements use distinct keys such as `outer_slot_seconds`, with unknown cost represented as `null`. Missing raw measurements are rejected rather than silently excluded. Existing output files are never overwritten.
