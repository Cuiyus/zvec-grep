# GLM local three-arm stability repeat

This fork-only experiment repeats run [38679000248](https://github.com/Cuiyus/zvec-grep/actions/runs/38679000248) with PR #261's updated statistics. It uses the same main 20-task corpus, OpenCode 1.18.4 and GLM-5.2: native baseline, published Node 0.2.2 + zg, and Rust `732a440` + zg. Each group has ten **new** trials per task (600 total), with local `potion-code-16m-v2` embedding (256 dimensions) for both zg groups.

The Node and Rust package artifacts are downloaded from the first run. `verify_reused_package.py` checks each manifest's source commit, the frozen tarball SHA256 and the executed CLI SHA256 before the package is republished for this run. Each task repeats this verification and verifies the installed CLI. Rust is not rebuilt. No prior Agent execution, answer, index seed or judgment checkpoint is imported.

For each task/group, sort ten results by score and then trial index, remove the first and last results, and use the same eight retained results for score, time and input tokens. Original samples and judge accounting remain intact. Each task has equal weight in aggregate means. The score rubric, model settings, question/reference files and usage accounting are unchanged from round 1; the new statistics code is checksum-verified against the updated PR.

The compatibility adapter retains Node's public command spelling and native binding 0.7.1. Task images are built once from their original Dockerfiles using the same immutable Ubuntu image; each trial uses a fresh container. Index seeds are keyed by source/package/model within a new task job. Eight task jobs run concurrently, with one Agent at a time inside each job. Group order rotates by task and repetition as in round 1.

Agent failures retain Harbor's maximum two retries and complete retry evidence. A failed execution slot prevents a complete task report; successful low-scoring answers are never rerun. Each new answer is self-judged once, with checkpoints keyed by its input digest. The new baseline judgments are reused for the two within-round statistical comparisons. `--collect-only` can finish collection/judging of intact completed evidence from this round without rerunning Agents.

`experiment.json` pins product identities, source run, corpus/statistics hashes and supplementary operations. Artifact names include the new run and attempt IDs. Per-task `report.json` retains all raw profiles; `comparison.json` and `report.md` show raw/trimmed means and retained/excluded counts. Reports from different rounds cannot be mixed. The stability comparison must apply the same updated statistics to both rounds and report raw/trimmed changes alongside failures and retries. No Retrieval benchmark is dispatched.
