# zg E2E 稳定性与 Prompt 对照测试 v1

状态：已接入 [原生安装实验 workflow](../../.github/workflows/native-qa-stability.yml)，首次 CI 实测待验证。承接 v6 的 E2E → 查询采集 → GroundTruth → retrieval-only → 联合报告，增加配置核验、固定状态决策诊断和 prompt 对照。新链路使用真实 `zg install`，不能与 v6 的自定义只读桥接结果直接视为同条件比较。

目标：在答案质量没有观察到下降的前提下，判断 zg 是否降低实际 input tokens 与工具调用，并定位重复运行的差异来源。固定 case 的五次重复属于初步验证，不证明小幅质量非劣、总体稳定收益或跨任务泛化。

## 1. 范围与运行配置

- QA：SWE-QA `reflex-6`；Reflex commit `fe0f946dc0c240c6c1e513318c21db407e191c78`，只读，不修改源码、不做增量索引。
- 检索：发布包 `@zvec/zvec-grep@0.2.2`，CPU 本地 embedding `local/potion-code-16m-v2`。各次 zg E2E 独立正常建索引，不要求索引冻结或跨运行哈希相同。回放按相同源码和配置重建索引，明确标为重建回放；保留构建与状态记录，对比实际返回和回放差异，不声称是原索引逐字复现。
- 集成：容器中实际执行 `zg config model set local/potion-code-16m-v2 --default --device cpu`，再执行 `zg install --target opencode|qoder --mcp-transport stdio --mcp-toolset agent --yes`。保留生成的 MCP 配置与 guidance；logging tap 原样转发调用和结果，只有 P01/P11 替换工具描述文本。发布版 0.2.2 的 agent 工具目录实际只有 search，原生 Agent 的 grep/read/glob 仍可选用；不开放 full 工具集。
- 组合：OpenCode `1.18.4` + GLM-5.2、OpenCode `1.18.4` + Qwen3.8-Max、QoderCLI `1.1.45` + Qwen3.8-Max。分别统计，不跨模型或服务混合 token 成绩。
- 保留现有只读权限和原生工具选择、执行、参数修复、并发、重试及结束行为。不新增程序化工具路由、强制 zg、自动修复、串行调度或新的结束规则。
- 本轮只改变 guidance 与 MCP description 文本；工具名称、参数结构、默认值、检索实现及返回格式不变。若必须改动这些内容，另立实验。

在开始模型实验前保存 `manifest.json`、`plan.json` 与 `selection.json`：源码、镜像、CLI、zg 与 embedding 身份；模型 ID 与端点；各臂完整 prompt 和有序工具目录；原题和答案评分标准；上下文、输出、思考与预算设置；执行顺序和随机种子。模型推理及压缩等未显式控制的设置按固定 CLI 的现有策略执行，并明确记录为版本固定／有效值未核验，不笼统宣称全部已固定。保存 prompt 与配置哈希，不保存凭据。

| 控制项     | 执行要求                                                                                                                                     |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 采样       | 两个 OpenCode 组保留 temperature=0，并核验实际发包。top_p 等字段按组合冻结；不同时调温度与 prompt。                                          |
| Qoder      | 核验固定版本和原生服务路径的实际有效设置；未核实字段标记 unknown，不以滚动文档或配置文件代替生效证据。                                       |
| Seed       | 仅在当前路径已验证支持后纳入。采用提前冻结的五个 seed，在同一时间块的各臂使用同一 seed；不承诺相同轨迹。执行顺序 seed 与模型 seed 分开记录。 |
| 模型漂移   | 固定可取得的模型快照与端点，记录返回 model、请求 ID、时间及可用 fingerprint；无法固定的服务端状态列为限制。                                  |
| 初始环境   | 各次独立会话、干净容器、相同仓库路径及配置来源；无跨试验会话记忆。每臂内核验起始输入与工具目录是否一致，各臂预期的 prompt 差异单独记录。     |
| 多轮上下文 | 冻结现有历史保留、压缩、输出上限及思考设置；记录真实压缩、截断、重试、终止原因。不能为了降低成本临时关掉某臂压缩或思考。                     |
| 预算       | 沿用三臂共同的 30 模型轮、60 工具调用、300,000 input tokens、900 秒预算与原生重试设置；记录在途操作造成的超限。                              |

模型参数需先通过请求构造及服务契约核验，再开始 prompt 比较。若控制参数需要变更，先冻结新的共同运行配置，之后三臂全部按新配置运行；不拿旧条件成绩作同期对照。核验无法观察的字段保留 unknown，报告相应解释边界。

## 2. Prompt 开发：固定状态下比较下一步决策

从冻结的历史轨迹提取决策状态，保留当时实际可见的完整消息、工具目录和已返回的反馈。每个组合最多五类状态：原始问题、精确搜索无结果、zg 返回相关入口、参数错误之后、已具有完整答案证据。后四类仅在已有轨迹确有该状态时收录；无实例记为缺项，不编造工具反馈。按冻结的 run ID 与轮次排序，各类选第一个符合条件的状态。证据是否充分在看候选结果前按源码和评分规则确认。

| Prompt 版本 | Guidance | MCP description |
| ----------- | -------- | --------------- |
| P00         | 当前     | 当前            |
| P10         | 候选     | 当前            |
| P01         | 当前     | 候选            |
| P11         | 候选     | 候选            |

每个状态、每个版本重复 5 次，只生成下一次原生模型决策，包括同一决策中的全部工具调用；不继续跟随新的轨迹跑完整 QA。只有 guidance 与 description 文本可变化，其余输入逐项核对。guidance 讨论适用场景及使用策略，description 解释能力和参数；不加入本题专属路径、符号、答案或标准 query。

诊断指标为工具选择分布、实际参数合法性、query 文本及完整请求的不同版本数、子目标相关性，以及可执行 zg 请求的已标注目标命中与排名。保留原始调用与 Agent 原生修复后的事件，不能用修复后成功掩盖原始错误。无 zg 调用、未知意图与执行失败分别保留；采用率不作为越高越好的单独优化目标。

状态回放必须先验证当前 Agent 与模型路径可恢复同样的消息及工具上下文。若只能把历史轨迹粘贴进普通 user prompt，或换用另一个模型端点，该实验不能称为忠实状态回放。无法恢复的组合标为不可用，不伪造可比结果；该组合仍参加完整 E2E。外部审计不得修改原生执行或帮模型选择工具。

诊断规模为 `可用状态数 × 4 个版本 × 5 次`。首次实现通过本地模拟模型响应捕获两个 OpenCode 组合的真实安装后初始请求，验证 guidance 恰好出现一次，捕获本身不调用付费模型、不计为 E2E。随后向原定真实服务回放这些输入，共 **2 个初始状态 × 4 版 × 5 次 = 40 次下一步决策试验**。Qoder 完整上下文不可观测、其余多轮状态尚未纳入，均显式显示缺项。每次可能包含多个工具调用；模型请求、工具、标注与回放成本单独计量。

筛选规则：先审查子目标和调用正确性，再比较检索效果与重复行为。候选若出现尚未解释的正确性退化，不晋级。没有明确改进证据时保留 P00，不从噪声中强选赢家。若多个版本均有依据，优先改动较少者；确定一个共同候选，冻结文本、哈希和选择理由，再启动全新 E2E。各组合的诊断可用性和差异单列；不挑出每组最优 prompt 后混为同一集成方案。

## 3. 完整 E2E：同期三臂、各五次

| 实验臂 | 工具与 Prompt                                      | 比较目的               |
| ------ | -------------------------------------------------- | ---------------------- |
| B      | 原生 read/grep/glob，当前共同任务指令              | 无 zg 的同期 baseline  |
| C      | 原生工具 + zg，当前 guidance 与 description（P00） | 当前 zg 集成的同期对照 |
| N      | 原生工具 + zg，已冻结的候选 prompt                 | 候选 prompt 的效果     |

B 不接收 zg 专属 guidance 或 description；共同 QA、任务要求、权限和预算保持相同。prompt 变长引入的实际 input tokens 计入成本。C 与 N 比较 prompt 的影响；C 与 B、N 与 B 分别比较当前和候选 zg 集成的收益。

每个 Agent+Model 组合安排五个时间块，每块包含 B/C/N 各一次；各块会话独立，不共享对话。各臂的先后次序提前随机生成，三个位置的出现次数尽可能平衡，任一位置最多相差一次；五个时间块无法严格等频。C 必须同期重跑，不能用历史 C 替代。所有顺序在看到答案或成本之前冻结。

三个组合 × 三臂 × 五次 = **45 个完整 E2E 运行**。该数量不包含参数核验、固定状态诊断、GroundTruth 标注、答案评审和检索回放。若未选出候选，可只运行 B/C 的 30 次，状态明确记为未进入候选验证。

确认阶段不边看结果边改 prompt，不替换失败样本，也不追加直到正收益出现。五次不足以作出结论时明确报告证据不足；增加样本必须预先登记新批次的固定数量、候选和终止规则，原批次结果仍保留。

## 4. 答案评审与收益判定

E2E 前冻结依据固定源码核验的原题事实、可接受证据和错误判定规则。答案评审隐藏实验臂、prompt 版本、模型身份及成本，使用固定评分配置；名称及答案风格仍可能间接暴露来源，记录这一限制。争议项按同一规则复核并保留理由，不让各臂生成自己的判卷标准，不因答案简短或调用少而加分。

| 层次     | 必须报告                                                                                                                                         |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| 质量     | 逐次必需事实覆盖、证据支持、实质错误、完整回答判定；计划五次中的通过次数。                                                                       |
| 成本     | 每次原生累计 input tokens、工具调用数、均值、中位数、范围；缓存输入与计费成本口径分别说明。                                                      |
| 配对比较 | 同一时间块 C−B、N−B、N−C 的 input/tool-call 差及五个差值的均值；不能把多个请求当独立 E2E 样本。                                                  |
| 不确定性 | 展示五个原始差值。可附均值差的双侧 95% t 区间（n=5，df=4），显式说明依赖独立、近似正态差值假设，只作辅助；不将其作为五次就能证明稳定收益的依据。 |
| 行为     | zg 采用次数/5、首次 query/完整请求/首批请求的重复情况、各阶段搜索及阅读次数、错误与原生修复。                                                    |
| 完整性   | 失败、超时、重试、缺日志、usage 缺失、预算终止及不可验证配置。                                                                                   |

失败和未采用 zg 保留在计划分母。展示全部可观测消耗，失败产生的低成本不能算收益；成功运行成本可另列，但明确属于有条件子集。usage 缺失记 unknown，不填零；缺项配对明确展示，不能宣称已得到完整五对成本估计。调用重试与恢复成本保留来源，不重复计量。

本轮优先检查质量退化，再看 input tokens 与 tool calls 的方向和波动。不合成自定义综合分数；两项成本方向不一致时报告取舍。质量标准暂不允许未解释的必需事实或正确性退化；如要接受微弱下降，必须在新的确认实验前明确具体事实和可接受范围，不能看结果后追认。五次都通过只代表本次观察，不等于统计上证明质量等价。

## 5. 接入同批次 retrieval-only 与解释链路

E2E → 收集原题及各轮实际完整请求和上下文 → 各组独立提出候选证据、源码与相关性核验 → 冻结共享 GroundTruth → 检索回放 → 联合报告。

沿用 v6 的共享标注规则：生成组不是唯一裁判，源码存在性不等于相关性；分歧保留 unknown。冻结状态试验产生的 query 与确认 E2E 的 query 分开归档和统计，不能混成同一次真实轨迹。实际请求保留模式、limit、融合、过滤和字段缺省状态；原始问题固定 hybrid、limit=10，单独报告。

每个唯一、可忠实回放的请求执行 5 次；第 1 次评价质量，其余检查一致性。使用 Hit@1/5/10、首个目标排名、RR@10、输出一致性和错误/unknown；不计算窗口命中与字节成本指标。原题、不同 Agent/Model、不同 prompt 及真实完整请求分别展示，不从三模式中择优。

逐次连接：实际请求与上下文 → 当时真实返回与目标位置 → 后续读取/搜索 → input/tool-call → 答案质量。新回放与旧返回不一致时先调查，不能用新结果替换当时 Agent 所见。相同上下文的模型决策差异、相同请求的检索差异、相同证据后的后续探索差异分别定位；未知服务端差异不能凭日志猜测根因。

query 重复度描述可观察行为一致性；排名与成本关联用于提出解释线索。需要定位 prompt 影响时回到固定状态诊断，局部决策实验不代替完整 E2E，也不自动证明某个 query 导致最终成本下降。

## 6. 交付与完成条件

交付运行 manifest 与顺序、四版 prompt 及筛选记录、状态快照与回放可用性、全部 E2E 原生轨迹和用量、盲评及分歧、共享查询 GroundTruth、检索回放与联合报告。报告首页列出计划/完成/失败/缺失数，以及本轮改动和未控制因素。

workflow 为 `validate → screen → e2e（三组）→ diagnosis`。screen 先完成真实安装和离线原生请求核验，才开始 40 次模型决策、共享源码标注与检索回放；没有足够证据选择候选则仅运行 B/C 共 30 次，有候选才运行 B/C/N 共 45 次。每个阶段分别归档全部失败与成本。所有 zg 安装、索引、Agent 调用均发生在隔离容器，源码只读；不修改宿主机的个人 Agent 或 zg 配置。提交标记 `[native-install] [retrieval-only]` 启动新 workflow 并跳过旧 v6 E2E。

验收是能够复核每次结果、区分质量与成本、定位主要差异，并给出“观察到收益 / 观察到退化 / 证据不足”的对应证据；不是必须跑出正收益。当前 reflex-6 明确为开发用例，prompt 在此迭代之后若用于对外宣称收益，需增加未参与调整的 QA。
