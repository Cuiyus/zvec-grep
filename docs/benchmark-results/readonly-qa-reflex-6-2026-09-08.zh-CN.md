原生事件解释了部分成本来源：baseline 共 30 次 grep、1 次 glob、51 次 read；zg 组有 9 次 grep、6 次成功 zg 检索、33 次 read，另有 4 次失败调用。Baseline 第二次运行出现多次猜词空结果，使其成本达到 170623 token / 33 calls，拉高了组均值。减少检索/读取轮次的同时，两组返回文本总量相近，说明本轮尚未同步压缩读取内容。以上是轨迹关联，不能仅凭工具统计证明每项 token 变化的因果贡献。

### 工具调用正确性

4 次失败尝试使用 `zvec_grep_search`，但 OpenCode 实际暴露的工具名为 `zvec_grep_zvec_grep_search`。原生事件明确记录 `state.status=error`，不会到达 zg sidecar；成功到达 zg 的次数分别为 **2、2、1、1、0**。10 次意图调用 zg 的尝试中有 4 次工具名错误，涉及 3/5 个 zg 试验。

第五次 zg 试验没有成功执行 zg 检索，但仍属于预先分配的 zg 组，必须保留，不能事后剔除。因而应将这里的对照解释为“给 agent 配置 zg 后的整体效果”，不能声称五次都实际利用语义检索获益。

CI 首版 observability 在 ATIF 转换后遗漏了这些原生错误状态。后续统计修正使用同一批原始事件恢复状态，并区分调用尝试与成功执行；原始 CI 报告保留，未重跑模型或替换试验。总工具调用和 input token 数字不受这一修正影响。

### 答案评分及抽查

按预设、带源码依据的模型评分，baseline 与 zg 均为 **5/5 通过**。评分模型同样为 GLM-5.2，属于同模型评分；这不是独立人工认证，也不是统计意义上的质量非劣证明。

后续源码抽查发现，核心解释链条基本正确，但自动评分漏掉了细节问题：

- Baseline 第四次把自动依赖分析描述为依赖信息的唯一来源，而 `reflex/vars/base.py:2433–2453` 同时合入显式 `_static_deps`。
- zg 第二次将依赖配对描述为也写入 `_potentially_dirty_states`，而 `reflex/state.py:798–800` 实际只加入状态名。

这些发现另行记录，不改写原模型评分。不能把 10/10 自动通过表述成“10 条回答完全无误”。

## Retrieval-only：执行稳定性与证据覆盖分开看

冻结原始自然语言问题，不用回答模型改写 query；FTS、vector、hybrid 各 5 次，`limit=10`。这层没有回答模型 input token；本地 embedding 计算与索引准备另计。

| 模式 | 请求成功 | 可见完整证据片段 | Raw item 完整证据片段 | 5 次结果顺序及可见文本 | 请求耗时均值 |
|---|---:|---:|---:|---|---:|
| FTS | 5/5 | 0/9 | 0/9 | 完全一致 | 189.5 ms |
| vector | 5/5 | 0/9 | 1/9 | 完全一致 | 209.4 ms |
| hybrid | 5/5 | 0/9 | 2/9 | 完全一致 | 217.3 ms |

Hybrid 的 raw items 命中 `_deps` 与 `_init_var_dependency_dicts`，但生产短预览只显示前 10 行，关键实现被隐藏。可见结果仍提供 `ComputedVar`、`_deps`、`DependencyTracker` 等文件/符号线索。**0/9 指完整标注片段未在短预览中出现，不代表零相关性，也不等于 QA 失败或全局 Recall 为零。** Raw evidence 不能冒充 agent 实际看到的内容。

当前证据规则要求每个完整源码片段在单条 observation 中出现，是保守下界。E2E 中，zg 第四次分两次 read 实际覆盖了全部 9 段，但单 observation 规则记录不足；第二次跨 read 合并后覆盖 7/9，仍未直接看到两段状态传播证据。此诊断补充了正式指标的含义，不事后更换冻结评分规则。

每种模式的 5 次调用在同一进程内，延迟包含首次 embedding 与后续调用，不含完整容器启动/准备；本轮未验证重新构建索引后的跨 CI 排序一致性。FTS 也不等于 agent + rg baseline，这层本身不能证明 E2E token 或工具调用收益。

## 本轮能支持的结论

“每次 CI 新建索引，再运行只读评测”的流程已经完整跑通。它暴露了三个具体后续研究对象：OpenCode 工具名调用错误、短预览隐藏关键实现、减少调用轮次后读取文本仍然较多。流程数据与原始轨迹能够解释这些现象。

本轮尚不满足“答案质量已充分验证，且 input token 与 toolcall 均稳定下降”的完整收益主张。保留当前 case 和所有负面结果；跨 CI 索引复用与 CI 提速仍按用户要求留待后续。
