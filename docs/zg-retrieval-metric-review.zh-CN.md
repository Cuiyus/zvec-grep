# Retrieval-only 指标有效性复审与修订

本次复审以提交 `d8cc881` 的 [zg short/full CI](https://github.com/Cuiyus/zvec-grep/actions/runs/35314877482) 和 [Semble CI](https://github.com/Cuiyus/zvec-grep/actions/runs/35314877473) 为依据。两者使用相同 20 道 SWE-QA 原题和 11 个固定仓库提交。本次调整评分与报告，不修改检索、问题、Gold、源码或历史输出。

## 结论

旧严格锚点指标有有限的展示回归价值，但不适合作为通用检索质量或答案证据质量的主迭代目标。Hit、RR、MRR 的标准公式没有问题；问题在于它们使用的相关性定义偏向声明入口和特定源码切分。

低分本身不说明指标无效。更直接的反证是：检索排名完全相同，仅改变输出展示就能改变分数；只显示声明可以得分，直接相关的正文却可能得零分。为提高分数而强制展示声明，未必改善用户获得的证据。

## 独立检查发现

| 检查项 | 结果 | 含义 |
| --- | --- | --- |
| accepted 目标 | 57 个：52 个 symbol、5 个 code span | 标签主要以符号入口组织 |
| 声明足以单独计分 | 全部 52 个 symbol，涉及 19/20 题 | 即使另有正文锚点，声明仍可作为 OR 替代项单独命中 |
| 全部锚点都只有声明 | 23 个目标，涉及 9 题 | 这些目标的正文没有独立获得命中的机会 |
| zg short 的计分见证 | 12 个 accepted match、10 道命中题的首个见证都是声明 | 这不表示输出没有正文，而是计分不需要正文 |
| outline 特判的实际影响 | 改善 django:21 首次锚点排名；没有改变 zg 的 Hit@10 命中题集合 | 不能把所有差异都归因于 outline，主要问题是声明标签与完整文本规则 |
| short/full 配对检索身份 | 100/100 对相同，但 3 题锚点 RR 改变 | 旧指标混合了检索与展示行为 |

[严格评分器](../benchmarks/zg-retrieval/scoring.mjs) 接受精确源码锚点或结果起始处的定义 outline；正文锚点则要求指定行的完整文本全部出现。[django 标签复核记录](../benchmarks/zg-retrieval/gold/v1/django-32.json) 明确记录了采用 declaration-only first anchors 的选择。该选择可以服务于入口导航诊断，但不证明获得了实现证据。

Gold 记录说明最初基于问题和固定源码选取目标，没有使用 zg 检索输出选标签；本次没有发现足以认定结果泄漏的证据。不过，两个 AI agents 的源码交叉检查不能替代人工盲审或与真实任务效果的效度验证。标签可能在概念设计上偏向某种产品形式，即使没有观察它的排名。

例如 `reflex:6` 的 `_deps` 正文说明如何把 `_fget` 交给依赖跟踪器，旧标签却只接受该方法的声明。`django:32` 的相关错误分支可以单独返回，但缺少长锚点中的另一分支仍不得分。反过来，`streamlink:14` 只找到文件头也能获得文件级 nDCG 满分，因此文件指标也不能代表证据充分性。

## 修订后的主表口径

主表的 Hit/RR/MRR 改为 **已标注相关文件定位指标**，与现有 Semble 官方算法 nDCG 使用完全相同的 `gold/semble-file-v1.json`：39 个冻结文件目标，仍来源于原有 accepted 目标，bridge-only 文件不计分。

对题目 q，令 r 为前十个原生结果中首次命中任一已标注文件的排名：

- `Hit@K(q) = 1`，当 r 存在且 r ≤ K；否则为 0。K 取 1、5、10。
- `RR@10(q) = 1/r`，当 r ≤ 10；未命中为 0。
- `MRR@10 = 所有可评分题目的 RR@10 算术平均`。本套完整运行是全部 20 题，零分题保留。

RR 是逐题值，MRR 是跨题平均，不能再把同一题的五次重复当作五个独立质量样本。主表 MRR 按题等权；Semble nDCG 的主汇总继续按仓库宏平均，两种权重明确标记。

匹配沿用 Semble 的路径匹配规则，仅检查公开返回路径；不要求函数签名、outline、特定文本、锚点完整性或片段行边界。保留原生结果排名，不将重复文件折叠后重新编号；仅调整源码展示不会改变新指标。

评分版本为 `sweqa-file-hit-rr-v1`。公开结果是唯一评分输入；缓存的派生分数不是依据。产品调用失败仍计零并使操作完整性失败；无效实验不能发布有效汇总；未复核标签不被悄悄计零。

## 对同一批历史输出重算

这张表比较不同评分口径，不表示检索系统在此次改动后取得提升：

| 指标 | zg short | zg full | Semble MCP |
| --- | --- | --- | --- |
| 新：文件 Hit@1 | 7/20 | 7/20 | 10/20 |
| 新：文件 Hit@5 | 10/20 | 10/20 | 15/20 |
| 新：文件 Hit@10 | 11/20 | 11/20 | 18/20 |
| 新：文件 MRR@10，按题平均 | 0.4056 | 0.4056 | 0.6267 |
| 不变：Semble nDCG@10，仓库宏平均 | 0.2925 | 0.2925 | 0.5599 |
| 旧：严格锚点 Hit@10，展示诊断 | 10/20 | 11/20 | 3/20 |
| 旧：严格锚点 MRR@10，展示诊断 | 0.1397 | 0.1960 | 0.0806 |

按文件 RR 逐题比较，Semble 领先 11 题、zg 领先 2 题、7 题相同。新的定位指标更有利于暴露 zg 的文件召回和前排排序差距。它不是以提高 zg 分数或使两产品排序符合预期为目标设计的。

旧严格锚点和互补组 nDCG 保留在独立的 legacy presentation diagnostics 表中，供查阅输出裁剪和固定入口变化。它们不再占用主表的通用 Hit/MRR 名称，也不作为整体检索优劣或默认质量门禁。

## 仍未解决的标签问题

文件级指标只是减少对展示形式的偏好，并没有让标签变成完整、独立的相关性真值。`reflex:6` 的依赖跟踪实现文件、`requests:16` 的 cookie preparation 辅助方法都有相关信息，但原有 accepted/bridge 划分会影响它们是否计分。

因此新名称保留“已标注相关文件”，不宣称完整召回、证据充分性或回答正确率。20 题的 Hit 变化粒度是 5 个百分点，适合作为小规模开发回归集，不能独立支撑普遍优越性的结论。

若要评价代码证据，应另行建立独立标签集：合并多种检索系统、关键词检索及人工寻找的候选，隐藏来源后按问题复核相关逻辑区间和可替代证据，并衡量标注一致性。运行阶段仍可使用确定性脚本评分。当前不通过临时增加新 agent 入口、任意一行重叠或宽松文本相似度阈值来抬高分数。

## 实现与兼容性

运行的原始请求协议、原始响应和两份 Gold 均保持原版本。新报告增加 `file_retrieval_contract`、逐题 `file_retrieval` 和按模式的 `file_retrieval` 汇总；旧 JSON 的顶层 Hit/RR 以及 `summary` 字段继续保留旧锚点含义，避免静默改变已有消费者。Markdown 主表和新字段使用新的明确命名，旧结果单独标为历史诊断。

离线版本比较从公开 `items` 和冻结文件目标重算新指标；旧报告缺少新派生字段时也可比较，新报告的评分版本与逐题缓存会被校验。CI 中 zg short、zg full 和 Semble 应用同一套计算，不修改产品排名或选择性剔除失败题。
