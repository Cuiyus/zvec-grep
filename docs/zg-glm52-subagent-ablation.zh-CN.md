# GLM5.2：子 Agent 与 ZG 对照实验

状态：实验准备与冒烟验证中，尚无正式结果。

本实验回答两个问题：**原生 GLM Agent 禁用委派后会怎样？在统一禁用委派的前提下，ZG 还有多少增益？**

## 对照设计

| 组 | 子 Agent | ZG | 用途 |
|---|---|---|---|
| `baseline_allowed` | 允许，由模型自主决定是否调用 | 无 | 同期原生对照 |
| `baseline` | 权限层禁用 | 无 | 隔离委派可用性的影响 |
| `node` | 权限层禁用 | Node 0.2.2 | 衡量禁用委派后的 ZG 增益 |
| `rust` | 权限层禁用 | Rust `732a440` | 衡量禁用委派后的 ZG 增益 |

正式执行原 SWE-QA 20 题，每题每组 10 次，共 **800 次、一轮**。四组在同一题、同一次重复内轮转执行；每题串行，最多 8 个任务并发。独立冒烟样本不进入正式统计。

主要比较方向：

- **禁用委派的影响**：`baseline − baseline_allowed`。
- **ZG 的增益**：`node − baseline`、`rust − baseline`。

这是“允许/禁止委派”的分组比较。允许组不强迫模型调用子 Agent，也不只挑实际发生委派的样本来估计效果。

## 保持一致与有效性检查

沿用历史 GLM 实验的题目、代码快照、评分参考、OpenCode 1.18.4、百炼 GLM5.2 参数、产品包、local embedding、超时与重试策略。三个禁用组只增加全局及各内置 Agent 的 `permission.task=deny`；允许组保留原权限设置。

真实 OpenCode 二进制配合本地模拟服务验证：允许时可产生子会话；禁止时 `task` 不出现在工具列表中，即使服务强制返回委派调用，`--auto` 和 `--dangerously-skip-permissions` 也无法创建子会话。

正式执行后检查每个尝试的配置、工具记录与会话树；失败重试同时检查归档目录和重试清单。缺失证据标为未知，不视为零。所有失败和重试保留，不以低分、高开销或未使用 ZG 为由剔除样本。

## 输出口径

| 指标 | 定义 |
|---|---|
| 质量 | 沿用原 GLM 评分器与参考答案，比较分数差 |
| 输入 token | 主会话和全部子会话之和，包含缓存输入 |
| 生成 token | 分列正文、推理；合计为两者之和 |
| 时间 | 主表为 Agent 执行时间，setup 与重试墙钟时间另列 |
| 行为 | 委派发生率、主/子会话 token、ZG 采用率、检索/读取/其他工具调用 |

主表保留全部最终答案样本，按题目等权汇总；失败重试的记录与成本另列。任务级结果和任务重采样区间用于检查收益是否集中在少数题目。

**解释边界：**本轮可直接比较同期委派可用性的影响。与历史三轮的对比仅为描述性参考，不能把跨日期变化全部归因于禁用子 Agent。本设计也不直接估计“ZG × 委派”的完整交互效应。
