# GLM5.2：子 Agent 与 ZG 对照实验

**已完成：20 题 × 每题每组 10 次 × 4 组，共 800 个最终答案。** 执行于 2026-10-22，分析完成于 2026-10-23。全部答案保留，按题目等权汇总。

**结论：子 Agent 可用性会明显改变 GLM 的探索开销；统一禁用后，ZG 仍提高 GLM 评分，但本轮未证明稳定的 token 节省。** 这里的评分是 GLM5.2 按既有参考答案给出的分数，尚未经独立人工评审，不能直接等同于客观质量。

| 对比（当前 − 参照） | GLM 评分差 | 输入 token 变化 | 生成 token 变化 | Agent 执行时间变化 |
|---|---:|---:|---:|---:|
| 原生禁用 − 原生允许子 Agent | −2.78 分 | **−24.03%** | −45.16% | −31.80% |
| ZG Node − 原生禁用 | **+5.33 分** | +9.74% | +2.00% | +2.09% |
| ZG Rust − 原生禁用 | **+5.53 分** | −0.61% | −1.98% | −4.62% |

输入包括缓存及全部主／子会话；生成包括非推理输出与推理 token。主表统计最终答案对应的 Agent 执行，不代表含安装、重试的端到端耗时或账单金额。另有 6 次 Agent 启动前安装失败，其缺失计量保留为未知，未当作零；800 个最终答案的证据均完整。

## 1. 对照设计与组均值

| 组 | 子 Agent | ZG | GLM 评分 | 输入 token | 生成 token | Agent 秒 |
|---|---|---|---:|---:|---:|---:|
| `baseline_allowed` | 允许，模型自主决定是否调用 | 无 | 79.77 | 112,716.73 | 2,516.46 | 57.81 |
| `baseline` | 权限层禁用 | 无 | 77.00 | 85,634.15 | 1,380.09 | 39.42 |

四组使用相同题目、代码快照、参考答案和模型设置，在每个“题目 × 重复”内轮转顺序；每题串行，最多 8 题并发。允许组不强制委派；未调用 ZG 的答案也进入统计。独立冒烟不进入正式结果。

|---|---|---|---|---|

区间来自对 20 个成对任务均值重采样 2,000 次（seed 42），反映题目组成变化时结果的敏感性，未另外重抽每题的 10 次执行，也不是未来单次请求的波动范围。禁用后的评分区间跨零，不能据此称“质量无损”；ZG 输入区间均跨零，不能称“普遍省 token”。

## 2. 子 Agent 改变了什么

允许组实际发生委派 **54/200 次（27%）**；三个禁用组均为零。允许组每次执行平均主会话输入 67,180、子会话输入 45,536 token；禁用后主会话输入增至 85,634。

因此，总输入减少 27,083 token，由“子会话减少 45,536”与“主会话增加 18,454”共同形成。主 Agent 承接了探索工作，不能把结果解释成直接删除子 Agent 的成本。

- 20 题中，12 题输入减少、8 题增加。SymPy 38、Pylint 9、Streamlink 14 占各题输入绝对变化之和的 51.48%，开销差异较集中。
- Agent 执行均时从 57.81 秒降至 39.42 秒；含 setup 和重试的 runner 每个逻辑执行均时为 **113.55 → 118.57 秒**。本轮没有观察到同等幅度的端到端提速。
- 这是“允许／禁止委派”策略的整体比较，包含主 Agent 策略与可用工具上下文变化，不能当作每次实际委派的因果效果。

## 3. 统一禁用后，ZG 如何改变检索

下表是每个最终答案的均值；工具计数包含全部会话。

| 组 | ZG 采用率 | ZG 调用 | grep / glob | read | bash | 全部工具 | LLM 请求 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 原生允许 | 0% | 0 | 4.55 | 5.37 | 0.92 | 11.11 | 8.24 |
| 原生禁用 | 0% | 0 | 3.70 | 4.03 | 0.77 | 8.50 | 7.29 |
| Node（禁用） | 93% | 1.26 | 1.60 | 4.08 | 0.10 | 7.04 | 5.95 |
| Rust（禁用） | 96% | 1.34 | 1.31 | 3.61 | 0.04 | 6.29 | 5.51 |

**ZG 主要替代了原生检索与部分探索轮次；后续读取并未同步消失。** Node 的 read 次数几乎不变，Rust 略降。Node／Rust 每次执行平均 ZG 回传约 11,479／13,863 字符，另有原生工具回传约 20,500／19,155 字符；原生禁用组为 30,994 字符。这些字符仅描述主会话返回量，不等于 token，也不能直接推出检索是否有效。

输入变化还需区分缓存：

| 组 | 缓存输入 token | 未缓存输入 token |
|---|---:|---:|
| 原生允许 | 99,368.32 | 13,348.41 |
| 原生禁用 | 76,307.20 | 9,326.95 |
| Node（禁用） | 84,650.88 | 9,324.33 |
| Rust（禁用） | 75,741.44 | 9,373.59 |

Node 相对禁用 baseline 多出的 8,341 输入 token，几乎全部体现为缓存输入增加；未缓存输入均值基本相同。故“总输入 +9.74%”不能直接解释成费用上涨 9.74%，也不能仅凭总量认定召回内容变多是唯一原因。

评分方面，Node／Rust 分别有 **14/20、16/20 题**上升；Conan 39 与 Streamlink 14 合计贡献净均分提升的 **60.28%／63.98%**。这两个占比以有正负抵消的净提升为分母，用于提示优先复核任务，不代表其余题目没有收益。

**Baseline 策略会改变“ZG 收益”的读法。** 同一批 Node／Rust 结果若参照本轮原生允许组，输入变化是 −16.63%／−24.49%；参照原生禁用组则为 +9.74%／−0.61%。前一种比较同时改变了 ZG 和委派可用性，后一种才是在双方都禁止委派时比较 ZG。这不等于已分解历史 ZG 收益的来源；本轮缺少 ZG＋允许委派组，历史实验日期也不同。

## 4. 三个行为案例与可检验的改进方向

三题在本轮结果出现前按历史子会话输入预选；代表轨迹按每题每组 input 排序取第 5/10 条，未按得分或是否委派筛选。单例用于解释路径，不能替代组均值。

| 案例 | 已观察到的行为 | 对应问题与候选方案 |
|---|---|---|
| **SymPy 38** | 允许组代表在委派前已将 “matrix entry” 理解成输入矩阵；子会话用 30 次工具，主 Agent 直接采纳报告。Node／Rust 代表都召回相关矩阵代码，后续读取范围不同，最后定位不同。 | 初始定位假设可能被后续探索放大。候选方案：围绕题目关键语义验证候选符号，委派返回后核对关键证据；不能仅归因于子 Agent 能力。 |
| **Conan 19** | Node／Rust 代表的首次召回均以 CMakeDeps2 开头，随后修改查询并广泛读取依赖图、Requirement 和测试。组均输入从原生禁用的 168,365 增至 226,037／190,488，评分 92.6 → 92.3／93.6。 | 工具次数少不保证输入少。候选方案：检索命中后围绕必要调用链读取，设定回答覆盖条件，减少无助于结论的扩展阅读。 |
| **Streamlink 14** | Node／Rust 代表仅用 3／2 次工具，定位不同的真实插件；二者都未覆盖参考的 CMMedia 链。单例评分 91／48，组均分却为 64.7／64.5。 | 题面未点名插件，需复核是否允许替代实现，以及评分标准与题面是否一致；不能仅凭该分差断定评分器错误。 |

冻结源码确认参考链仍存在：[SymPy minorEntry](https://github.com/sympy/sympy/blob/3c817ed8ab551d71e36907ce869afe5e4ca789ff/sympy/matrices/matrices.py#L675-L676)、[Conan Requirement](https://github.com/conan-io/conan/blob/52f43d98fe44ab92d01317110488d0670c3e9e64/conan/internal/model/requires.py#L220-L242)、[Streamlink CMMedia](https://github.com/streamlink/streamlink/blob/ab1f36560005253ca6a290a614730bf18a29a7f9/src/streamlink/plugins/cmmedia.py#L38-L126)。Streamlink 两条答案的主要替代实现链可由实际读取内容核验，Rust 有一处返回容器形状表述不准确；评分缓存只保留五项整数，没有文字理由，无法解释全部 43 分差。

## 5. 建议专家重点判断

> 在这 20 题、800 个答案的同期实验中，禁用委派降低了 GLM 的输入与生成量，但评分均值下降；双方均禁用后，ZG 提高自评分，却未呈现稳定的 token 节省。行为证据显示，委派会改变探索规模，ZG 会减少原生检索，但召回后仍可能继续广泛读取。同时，少数题目的目标是否唯一、替代实现能否接受，会影响评分的解释。我们拟先复核题面与评分标准，再测试“有明确目标的委派”和“命中后收敛读取”的引导。这样的归因和改进顺序是否合理？是否遗漏了更关键的行为机制或评估偏差？

建议的后续步骤（尚未执行）：

1. **先复核已有答案**：优先人工盲审 Conan 39、Pylint 9 的大幅评分变化，以及 SymPy 38、Streamlink 14 的目标歧义。分别判断代码事实、题意覆盖与评分尺度。
2. **再做定向行为实验**：固定题目与权限，单独比较现有引导与“验证定位假设、限制扩展阅读、满足覆盖条件后作答”的引导；同时记录回传大小、后续读取和独立评分，验证是否减少成本而保留效果。
3. **需要估计交互时补齐实验**：增加同期 Node／Rust＋允许委派组。若要解释 Qwen 与 GLM 的差异，还需在 Qwen 上采用同一设计；本轮 GLM 结果不能替代该对照。
